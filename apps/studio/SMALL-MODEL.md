# Small model decisions

Qwen still requires context. The local server uses a 2,048-token window; both inference paths count input and reserve output before generating. Oversized decisions fail visibly instead of silently truncating user instructions. Route output is capped at 160 tokens; argument output at 384. Qwen's chat template disables thinking.

A coordinator delegates bounded subtasks to separate specialist harnesses. Each specialist has its own task, scoped context, tool allowlist, trace and completion status. Website, PDF, Babylon scene, existing Stripe Payment Link, public research, workspace, local video and public video-source specialists are available only when their tools are granted by the host. Video recipes and recording transcripts are retrieved in small pages; see [VIDEO.md](VIDEO.md). Ordinary conversation can finish directly without delegation. All agents reuse one model sequentially; delegation does not allocate more model weights.

The coordinator has delegation and task-evidence tools, rather than direct editing tools. Completed tasks can supply explicit handoffs to later specialists. An agent can read only the input tasks it was assigned. Network agents cannot receive private specialist handoffs or saved private context. Local chat keeps both website and PDF capabilities available when a PDF is open.

Every run shares a maximum of 48 model calls, 18 host-tool actions and six delegations. Specialist harnesses have six decision steps and the coordinator seven; two consecutive failures stop a harness. Cancellation propagates through every role. Canonical action fingerprints prevent repeated mutations across subagents, including when JSON key ordering changes. Failed attempts may be retried after satisfying a missing prerequisite; only successful edits enter the duplicate guard.

Website and scene specialists inspect current state before planning and get a host inspection after writes. PDF specialists must inspect each target page before editing; the host reads the affected pages again afterward. Each delegated PDF task is limited to 16 affected pages. Verification consumes the shared tool budget. Failed, unverified, limited or empty tasks cannot be presented as completed by the coordinator. Verification establishes structural execution evidence, not semantic correctness of every user request.

Additional tools can be registered in trusted host code through `OrchestrationOptions.profiles`, declaring a tool allowlist, context keys, contract and verification tool. The model cannot register profiles or grant capabilities. Unknown write tools require an available host verifier before execution. This is the extension point for future tools; no email sending or arbitrary shell execution was added by this change.

An immutable working evidence store holds the complete initial context and tool results outside prompts. Each call receives previews of at most 450 characters per evidence record, marked partial, plus references. `read_evidence` retrieves a JSON pointer or a 900-character page. Local completed traces are retained by SQLite; website and PDF revisions retain edited state. Browser references currently last one turn. This is not unlimited long-term conversational memory.

Voice finishes after 650 ms of silence following sustained speech. Loaded browser models survive normal interruptions. Qwen cancellation stops generation at the next stopping-criteria check. Speech starts with a short sentence and prepares the next chunk during playback. These changes reduce waits; first-time downloads and CPU inference still take time.

References reviewed: [Odysseus compact routing](https://github.com/odysseus-dev/odysseus/blob/dev/src/agent_loop.py), [OpenAI turn detection](https://developers.openai.com/api/docs/guides/realtime-vad), and [Grok voice latency](https://x.ai/news/grok-voice-think-fast-2). The Odysseus source has compact tool routing and context budgeting; a specifically parliamentary implementation was not identified. The chair/proposal/record design here is our interpretation, not a claim about that project's architecture.

Verification: 26 tests pass, including website/scene/workspace orchestration, video-source handoffs, cross-agent permissions, shared budgets, duplicate prevention, public research handoffs, private handoff rejection, PDF inspection/verification, extension verification, literal-operation grounding and cancellation. Real FFmpeg tests cover narration, still images, captions, trimming, speed, framing and source preservation. A separate online probe downloaded a real video, captured a public webpage and decoded a rendered MP4; the actual Etro React component played its video/image/text layers without browser errors. Scripted decisions test host contracts, not Qwen's creative interpretation accuracy. The 2,048-token limit remains enforced for every coordinator and specialist call.

The separate `scripts/probe-orchestrator.ts` check uses actual Qwen3-0.6B Q4_0 with llama.cpp on four CPU threads. After runtime initialization it completed a delegated title change in 2,662 ms across three model calls: coordinator choice, task contract, specialist arguments. Host inspection verified the exact requested title. This excludes voice and does not establish reliability for arbitrary multi-step work. The official GGUF download was SHA-256 verified. The installed llama.cpp runtime requires `--reasoning off`; merely setting the template's `enable_thinking` caused its structured-output sampler to reject requests.

Literal copy instructions use a host-defined operation contract: narrow the tool and field, ground the new value in the original user request, constrain arguments, execute and inspect the saved value. Verified completion returns immediately instead of asking the model to re-decide whether an observed fact is complete. Open-ended work retains its loop and can request details. Handoff argument schemas enumerate actual completed task IDs and require an empty list before any task exists. Known action requests begin with delegation, and editing specialists cannot select `finish` before executing a write; they may ask for missing information.

A subsequent tokenizer check exercised 11 coordinator/specialist calls for a website title change followed by a Babylon sphere. The largest call used 723 tokens including its output reserve. Those decisions were controlled by the verification script; this is a context-budget measurement, not inference accuracy.

Updated browser CPU speech verification produced the first short chunk in 3,858 ms after loading cached models and the second in 1,116 ms. These measurements exclude recognition, Qwen generation and playback.
