# Persistent software builds

Software requests now enter the local /api/software task service. The full goal, extracted acceptance requirements, workspace revision, tool evidence, phase history and model-call counts persist in SQLite. Backend restart requeues interrupted tasks. Closing the conversation or panel does not stop the builder. Explicit Stop preserves the workspace; Resume continues it.

The worker plans from paginated goal evidence, creates and edits files, copies selected public Anascummis modules, reuses the user-owned OnlineSlop source recipe when requested, runs actual verification and reviews acceptance. Twelve work turns form a scheduling slice; a slice ending requeues work rather than reporting completion. Work continues while progress is made. Three consecutive failures, repeated mutations or 96 decisions without source/acceptance progress require attention. There is no fixed one-day deadline. Small-model failures remain visible, never converted into success.

The native runner installs pinned registry dependencies without lifecycle scripts, checks TypeScript, runs Bun tests, builds Next.js through Node, launches the production app and captures real browser DOM/screenshots through a separate headless browser. Windows packaging embeds traced Next.js output and Node in a Bun executable, then launches the executable and checks its HTTP response. Only completed tasks expose verified downloads. Model weights and FFmpeg remain separate dependencies when the generated app requires them. Native generated code executes with the current user's permissions; this is a trusted local build workspace, not a security sandbox.

The Software work floating FlexLayout panel shows persistent milestones, failures, screenshots and artifacts. The assigning orb can report progress without occupying foreground inference. Completion estimates require at least two verified milestone work durations and are labelled low confidence; initial estimates remain unknown.

The public orb pairs with the local builder using a private key shown inside the local app. The browser connects only to a loopback address, authenticated by that key; the key remains in session storage and never goes to the model or Cloudflare relay. Browser local-network permission may be needed. The public Worker itself does not run builds. Without pairing, the panel keeps the full requested goal until a builder is connected.

## Evidence and capability limits

A real persistent task, using local Qwen for a bounded exact-heading operation, completed its component test, production-browser heading assertion, Next build, source ZIP and Windows executable launch in approximately 146 seconds. This is a simple predefined recipe, not evidence that Qwen autonomously authored OnlineSlop. The generic worker and reusable recipes provide a connected path for larger tasks; the full OnlineSlop acceptance test remains unproven. OnlineSlop reuse records source hashes/provenance and excludes private recordings, OAuth credentials and model caches.

The earlier unrestricted Qwen source-routing probe failed after two invalid evidence reads; host-selected reading worked. These observations remain material. Automated source/test/DOM review cannot establish journalistic accuracy, subjective video quality or pixel-level visual QA. A screenshot is real evidence for human inspection, not a claim that a text-only model saw it.

An additional real counter-generation test failed: Qwen emitted invalid source and then truncated its repair JSON. It was retained as needs_input with compiler evidence and no released artifacts. Failed check results are now cached per workspace revision and compiler diagnostics direct small-file repair steps. This remains evidence that arbitrary software authorship is not yet reliable.

The same failed counter checkpoint subsequently completed at revision 2 using the numeric React screen skill. Qwen supplied initial=0, delta=1 and accessible control labels; a host compiler emitted React syntax. Independent production-browser clicks verified 0 → 1 → 2 and reload reset, followed by a clean source ZIP install/test/build. This is constrained skill composition, not general free-form Qwen coding. The numeric skill is also exposed to generic software tasks; arbitrary-source and larger application acceptance remain separate.

The general-worker probe also exposed repeated catalog reads and unreported successful checks. The worker now prunes irrelevant tools, grounds inspected file names in schema enums, remembers read pages per revision, excludes unchanged reruns, verifies source revisions immediately and supplies current successful QA evidence to each decision. Counter-skill scope is explicitly closed: additional PDF export, persistence, different arithmetic or unrelated features are never absorbed into that acceptance contract. Missing browser controls now fail in five seconds rather than waiting for the process timeout.
