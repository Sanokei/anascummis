The first supported runtime executes the **actual accepted counter/collection client Page**, compiled with matching installed React into a fixed browser wrapper. Exact ZIP checks, known compiler source/provenance, dependency versions and derived runtime manifests gate preparation. No arbitrary Next/model-written server runs, no dependency is installed and no model is called. Other apps retain their source ZIP/manual instructions. This narrows the earlier [source-backed plan](../2026-10-29-app-launch-plan/PLAN.md); its official origin/storage/cookie/IPC sources remain applicable.

Acceptance:

1. Prove owned IPC readiness, successful saved-port bind, exact runtime identity, awaited Stop, and worker exit after owner SIGKILL. An unrelated HTTP200/occupied port must fail without attachment, port changes or unknown-process signals. An exited zombie is not a live listener and is labelled accurately.
2. Prove the actual separate-origin sandbox can save/reload collection items while parent DOM/storage/top navigation/popups/Studio fetch are blocked. Cookies can reach the fixed edge because ports do not isolate them; strip every credential before fixed asset handling and discard response cookies, logging only counters. Do not claim a hostile-code sandbox.
3. Prepare real previously accepted counter, My Tasks and My Week ZIPs deterministically, preserving their source/records/downloads. Reject unsupported source, CRC/path/duplicate/compression/symlink tricks, stale checks, missing matching dependencies and self-consistently forged runtime caches.
4. Expose explicit Start/Stop and source/runtime/address identity in the existing local Software card. GET/poll/mount/reopen/reload never starts a process. Stop during preparation and stale responses cannot resurrect a view. Unconfirmed actions require status inspection and a deliberate retry. Paired online launch is refused.
5. Through ordinary product buttons, use the actual iframe on desktop/360px: Add/keyboard/duplicates/individual Remove/reload, and counter Increment/Reset/focus/feedback. Closing/reopening keeps the same launch identity; Stop followed by Start restores the view. This reuses native-generated work, not fresh inference.
6. Graceful and forced Studio restart remove owned listeners, preserve interrupted state and require explicit same-origin Start with retained items. Explicitly stop the parent and start a compatible child at the same address; keep parent records/ZIP/source exact. No silent fallback or data transfer across origins.
7. Keep launch state separate from accepted build bodies; append real launch activity in the existing history. Exercise idempotency, two-active-lineage bounds, rollback, source/port failures, cleanup, missing dependencies and stopping even after eligibility becomes false. Run affected software/download/revision/recovery and read-only navigation checks, both TypeScript targets, explicit worker types and production build.
8. Preserve original failure receipts and screenshots; share an additive source-pinned pack with the actual tested lifecycle and limits. Refresh the current source handoff after material code changes while keeping frozen kits. No main promotion, public deployment or native OS/voice claim.
