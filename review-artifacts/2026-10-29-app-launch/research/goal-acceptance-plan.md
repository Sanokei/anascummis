# Product launch user-goal acceptance

This is launch of stopped, previously native-generated accepted work, copied to owned test data. It is not fresh inference, an E2E-owned substitute app server, an online dependency install, or a native-device proof. The product manages the actual fixed trusted React runtime from the exact accepted Page ZIP. Original source records/ZIPs/databases stay unchanged.

## Positive journeys

Run the ordinary production Studio UI with actual completed My Tasks/My Week and Bakery Orders checkpoints, at desktop 1440×1000 and touch-emulated 360×800. Preserve all original receipts and before/after source, driver, dependency and served-build fingerprints.

1. Open Software through the visible typing path. No app starts on mount, GET, window opening or page reload. Inspect exact source revision/ZIP/runtime identity. Use the card's explicit Start app and the product-managed separate-origin iframe.
2. My Tasks: keyboard Add, pointer/touch Add, distinct duplicate items, individual Remove, embedded reload persistence. Close/reopen Software and reload Studio retain the same process/launch/runtime identity, items and origin, with no additional Start, preparation, model call or POST.
3. Stop awaits the owned process's exit and removes the iframe; explicit Start reuses its saved address/items. Graceful Studio shutdown and forced SIGKILL remove the owned listener. New Studio starts interrupted/stopped, without automatic execution; an explicit Start restores the same-origin items.
4. Explicit Stop(parent) then Start(accepted My Week child) retains the same lineage origin and exact existing items, permits further edits/reload, and preserves parent source/record/ZIP and model-call counts. Redownload and checksum actual accepted ZIPs.
5. Counter: actual embedded 0→1→2→Reset0, touch/pointer and Tab/Enter/Space, visible native focus and feedback, reload0, explicit Stop/reopen. Its accepted source ZIP and record remain unchanged.

## Failure and boundary journeys

- Real Start accepted by the host but its browser response deliberately dropped: show unconfirmed delivery, inspect through GET, preserve the same saved process and one Start POST; never replay automatically.
- A duplicate Studio process on the same data/address fails its bind without changing the original running app's launch identity, state or update time.
- After an owned Studio restart, retain the old browser tab and a genuine unsent composer draft. A status GET receives the real session403; explicit Reconnect to Studio fetches the ordinary HTML/session and status without navigation or POST. The draft survives, the app remains interrupted/stopped, and only a later deliberate Start restores it.
- An aborted status GET while the real host remains healthy preserves the actual iframe DOM identity and unsubmitted app input. An explicit real GET clears the uncertainty without restarting/preparing the app.
- Stop request deliberately dropped before host delivery: show unconfirmed state, keep the real process active, inspect through GET, and require a deliberate retry. The test labels this transport interruption; it supplies no fake API reply or inference.
- Occupy the saved address with a separate owned HTTP200 listener. Explicit Start must fail visibly without attaching to it, killing it or selecting a new origin. Closing that owned blocker and explicitly retrying recovers the same saved items/address.
- Actual iframe storage works while reads of parent DOM/storage, top navigation, and Studio HttpOnly cookie reads fail. Fixed-worker spike separately proves cookies can arrive at the host edge (ports do not isolate cookies), but sanitized app-facing handlers receive none; responses carry no app Set-Cookie. No raw credential values enter reports/logs.
- Contract-only rejected API probes (outside browser tracing) use the real current local session and pairing key in memory: valid paired-online launch still403, unknown Start command fields400. Record only status/error and unchanged launch state; never record credentials or seed mutation state.
- Package/unit/spike owner checks cover unsupported code, unsafe ZIP paths, missing or mismatched dependencies, tampered runtime/ZIP identity, IPC bind/identity, stopping during preparation, stale callbacks, and no blind saved-PID ownership.

The driver only uses normal UI mutation controls plus read-only API inspection. It copies fixture data without installed/build caches, explicitly links each task's original matching dependency tree, and never seeds API/database mutation state. Public reports include selected originals and checksums; private data, raw host logs and full dependency/build trees remain local. A failed or blocked useful outcome cannot become a completed goal merely because a recovery control exists.
