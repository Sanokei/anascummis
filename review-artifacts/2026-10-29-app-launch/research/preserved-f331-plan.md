**Four unresolved design gates, grounded in primary sources.** Exact URLs, retrieval times, sizes and SHA-256 are in [sources.json](next-launch-research/sources.json); full documents stay local.

1. **Iframe/storage:** WHATWG iframe/origin/Web Storage specs say sandbox defaults to an opaque origin, `allow-same-origin` restores the child's real origin, and origin equality includes port. Scripts/forms require allowances. Scripts plus same-origin permission on content actually sharing Studio's origin can escape sandboxing. Prototype a genuinely separate origin with `allow-scripts allow-same-origin allow-forms`, no top navigation/popups/downloads; prove actual embedded storage/keyboard/CSP. Never use Studio-path proxying/srcdoc. Iframe removal has no guaranteed unload event and cannot authoritatively stop a process.
2. **Cookies:** RFC6265 §8.5 explicitly says cookies are **not isolated by port**. Studio's HttpOnly cookie is host `127.0.0.1`, Path `/`; another port alone does not keep it out of app HTTP requests. Prove proxy credential stripping and rejected response cookies. This trusted-compiler scope is not hostile-code/process isolation; arbitrary apps need a broader design.
3. **Ownership/cleanup:** Bun documents JSON IPC for Bun↔Node, `onExit` and awaited `exited`; Node documents disconnect and that kill signaling does not establish termination or descendant cleanup. Prove a fixed host-owned launcher reports actual successful bind/runtime identity, rejects unrelated HTTP200, awaits owned exits and cleans up after parent SIGKILL. HTTP200, iframe load and persisted PID alone are insufficient. No blind PID reattachment/kill or untested Next-internal dependency.
4. **Runtime identity:** Next standalone requires static/public assets. Prove accepted-ZIP→separate immutable runtime preparation with existing dependencies and real checks. React effects can repeat setup/cleanup, so Start/Stop must be explicit events with server idempotency, never mount/unmount effects.
