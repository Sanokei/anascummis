# Native editing acceptance audit

## Existing seam

`core/pdf.ts:editPdf` directly increments the current revision without an expected base or durable operation key; `core/goal-executor.ts` initially provides only page 1. It is useful for bounded immediate edits but does not establish proposed-change acceptance or no-duplicate retry across host interruption. The existing source-brief store already preserves an accepted structured input, a raw native writing decision, and immutable original PDF/HTML bytes; reuse this as the bounded starting class.

## Concrete user goal

Use the accepted two-page Fetch contributor brief, with its complete 1,719-character personal handoff. Rewrite only its factual summary into two short sentences: first beginning “Tests:” and second beginning “Browser results:”. Preserve both exact locations and citation numbers, the existing complete personal notes and all original evidence. Improve ordinary source quotation/link formatting and move machine provenance into an explicit detailed appendix/view.

A model proposing that focused factual rewrite is a genuine local decision, but rendering a known structured brief does not establish arbitrary imported-PDF editing or arbitrary model-authored application execution. The exact complete notes should be host-pinned/preserved and remain inspectable; the small local model need receive only the focused edit packet it actually reads.

## Required lifecycle

1. Start from an isolated copy of the previously accepted real-native two-page fixture. Record full source fixture fingerprints; never modify normal user data.
2. Open the accepted original through ordinary Goals/reader UI. Capture one original page and its version/source identities.
3. Enter exact edit intent. Close/reload before send; require preserved draft and no mutation. Submit explicitly; abort only an already-delivered UI acknowledgement. Inspect saved operation through GET; exactly one linked child/operation.
4. Stop native planning, reload, explicitly continue. On a saved genuine native proposal, retain raw JSON/hash and exact before/after diff. Kill only owned Studio process before publication. Restart into needs_input and verify no automatic infer/write replay; inspect and continue deliberately.
5. Explicit Apply must create exactly one durable revised artifact/version even if its acknowledgement is lost. Inspect, reopen and export without repeating edits. Original PDF/HTML remain byte-identical, original source/answer/notes identities unchanged.
6. Independently open/render actual revised PDF and exact downloaded HTML. Check the requested two-sentence rewrite appears once, complete original notes remain, cited facts/targets match, no raw quotation Markdown/fragmented printed URLs in ordinary body, detailed provenance retains exact quotes/raw hashes/IDs. Verify usable desktop,360x800 and360x420 proposal/recovery/actions.
7. Report blocked or failed genuine native outcomes as unmet; preserve raw failures. No policy bypass, new model download, normal-data seed, public endpoint or inferred handset/native-OS/voice quality.

## Primary sources and implications

- SQLite transactions: https://www.sqlite.org/lang_transaction.html. Explicit transactions give DB commit/rollback; BEGIN IMMEDIATE can fail SQLITE_BUSY with another writer. This does not make filesystem output and SQL one atomic unit, so stable paths/identities and restart reconciliation still require host checks.
- Playwright downloads: https://playwright.dev/docs/downloads. Wait for the Download event, call saveAs, and preserve actual browser bytes before context closes. Inspect exact-URL GET headers separately and require byte equality; do not infer file type from a filename or success toast.
- Official llama.cpp grammar docs: https://raw.githubusercontent.com/ggml-org/llama.cpp/master/grammars/README.md. JSON schema constrains generated syntax and is not injected into the prompt; expected structure must be described explicitly. Subset/unsupported features mean host validation remains necessary. Grammar validity is not semantic edit quality.

Each fetched primary body, byte count and SHA-256 are retained in sources.json.
