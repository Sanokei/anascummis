## Implemented host contract and its limits

The explicit target is separate from the unchanged original request. Read-only paragraph options include the accepted base revision, complete notes hash and exact ranges/hashes. Fresh edits have no section or format default. Drafts retain partial choices, stale identities, older labels and submitted snapshots rather than silently replacing them.

The same submission key must match intent, section, paragraph/hash and format. A note proposal's Apply identity binds the target, unchanged summary and complete proposed notes; an unchanged summary alone cannot authorize a different note replacement. The host reconstructs the exact raw replacement at the pinned range and preserves every unselected character and separator. Effective current notes remain separate from immutable original research provenance, and later supported edits inherit accepted notes instead of resetting them.

Literal checks reject copied/punctuation-only or deletion-only output, lost timing/future status, new completed-work claims and new URLs. A narrow additional guard rejects the observed regression **“I will observe the outcome I expected and what I actually saw”** when the original planned recording those outcomes; past “what I observed” inside a recording object remains valid. Explicit opposing-section requests, including “Revise the factual paragraph” with Notes selected, and selecting a section the request says to preserve require clarification before a child is created.

A proposed note must also pass all native meaning/action/tense/clarity flags before Apply becomes available. These regexes and same-model flags are limited checks, not independent semantic verification. Actual language still needs critique. [Final source audit](independent-review/independent-section-source-review-final.json) records the exact code scope. Historical v1/v2 HTML and provenance plans reproduce their previous bytes unchanged.

The affected host/fixture suite passed **68 tests / 1,565 assertions**. Separate focused final checks passed the alias case **1 / 85** and observed future-observe case **1 / 71**. Both TypeScript targets and production build passed. Counts are separate; earlier overlapping subsets are not added again. Injected successful note responses, real PyMuPDF file tests and simulated crash/conflict cases establish host behavior with those supplied decisions, not genuine native note-writing quality.

[Independent checkpoint review](independent-review/independent-section-checkpoint-review.json) verifies the 92 indexed original copies, all seven PNG identities, the stopped desktop/phone database history and retained raw response, unchanged pre-existing rows/files and the final kit. This is artifact/scope verification; it explicitly retains the native goal as failed.
