## Source-backed seam

`tools.ts` already provides read_public_page through `network.safeFetch`, but returns transient text clipped to 9,000 characters without content identity/title. `analysis-harness.ts` checks exact supplied-source quotes but has no durable question/source linkage. `work-journal.ts` intentionally omits tool results, and foreground answer streaming has no durable research record. Goals persist dependent tasks/evidence and have stop/restart/continue guards, but require inference to plan a read and transfer only bounded evidence strings. Native inference is unavailable, so a supplied public URL cannot currently become an inspectable retained source/answer job before planning fails.

## Observed corrections within this acceptance path

- The first ordinary browser run retrieved real sources and reached native `needs_input`, but tapping the visible Goals Close control failed. Hit testing showed the shared layout's `pointer-events:none` was inherited by its tab header, passing taps to the window content. Enable header/tab pointer events and verify a real touch close/reopen plus keyboard Control+Delete; no forced click.
- A delayed protected saved-text GET reproduced another close race: closing the reader while Next text was pending reopened it on the late response. Abort/retire that view's read on close/unmount, reject stale delivery, and permit a fresh explicit Inspect. This affects only inspecting the retained copy; it never retries a public fetch or task mutation.
- Plain text remains verbatim, including markup-like code. Only an actual top-level Markdown heading or an HTML title supplies a document title; a subsection cannot replace the filename fallback.
